# CEML-FRONTIER-1 — frozen interval-verification protocol

**Version:** CEML-FRONTIER-1, frozen by cloud-only P2 on 2026-10-11. **Scope:** specifications, not an implemented or validated verifier. **Status:** P2 protocol PASS only. L1 and RUN1 are separately gated.

## 1. Mathematical trust and exact inputs

The map on positive integers is `T(n)=n/2` for even `n` and `T(n)=(3n+1)/2` for odd `n`. Convergence means a finite orbit reaches 1; `T(1)=2`, not 1. A separately accepted externally evidenced proposition `A(B)` asserts that *all positive n<B* converge; it is never proved by reading a website or passing local software tests. All interval endpoints and internal trajectory values are exact arbitrary-precision integers (subject to explicit resource refusal, never silent narrowing). Every scientific batch `[S,E)` is nonempty, `S>=B>=2`, ascending, and has `E-S<=14400`. Any start `S>B` requires a verifiably committed contiguous chain starting at `B` and ending at `S`. Thus a published-base run cannot jump across the peer-reviewed-to-live gap. A distinct author-reported-base run may begin at its recorded operational `B`, but inherits that weaker external assumption forever. Chain roots cannot cross modes or snapshots.

Canonical rule precedence, with no extra sieve or Tao-based exclusion:
`E2 > Q4 > P3 > M9 > S2K4-03 > EXPLICIT`.
Use the exact domains and proofs of `docs/P1_EXCLUSION_PROOFS.md` (P1 `PROVED` only conditionally on ascending `A(n)`). An integer is assigned to its FIRST applicable rule. The reference independently recomputes its witness: E2 forward `n/2<n`; Q4 forward `T²(n)=3(n-1)/4+1<n` (n>=5); P3 odd predecessor `p=(2n-1)/3<n` and `T(p)=n`; M9 predecessor `p=(8n-5)/9<n` and `T³(p)=n`; S2K4-03 forward `T⁴(n)=(9n+5)/16<n` on `n%16=3`, `n>=3`. All divisions exact. `n=1` is outside frontier batches and handled solely as a unit-test/below-base boundary; no Q4 on n=1. `EXPLICIT` evaluates exact T until the **first** positive iterate smaller than its ORIGINAL n; under valid ascending induction this is sufficient. A resource/step ceiling or non-descent is UNRESOLVED, never a convergence inference or proof of divergence. A rule's finite theorem-backed witness is a *logical inference*, not evidence that a CPU executed the trajectory.

### Tiny table built, not trusted

At build, independently generate all 16 length-4 parity words from the definition-level T recurrence (allow T(0)=0 only for table derivation); compute affine `a,b` and exact quotient for each residue. Verify independently with the other recurrence `(a_0,b_0)=(1,0)` and for step j: on odd `(a,b)->(3a,3b+2^j)`, on even unchanged. Independently compute the universal inequality, checking q>=0, and permit ONLY residue 3 modulo 16 with parity `1100`, `a=9`, `b=5`, `T⁴(16q+3)=9q+2`, `16q+3-(9q+2)=7q+1>0`. All other table entries must be checked but never used for exclusion. Pin the canonical table text/hash in the build manifest and certificate; mismatch REFUSES. The separate Python reference must derive its own table and witnesses without importing native helper code, precomputed native rows or shared precomputed verdicts.

The complete period-144 residue assignment counts are E2 72, Q4 36, P3 12, M9 4, S2K4-03 5, EXPLICIT 15. In mod-144 order M9 residues are 31,67,103,139; S2 residues are 3,19,51,99,115; EXPLICIT residues are 7,15,27,39,43,55,63,75,79,87,91,111,123,127,135. Independently derive the entire assignment array by predicates in Python and compare the pinned reference truth table. For arbitrary [a,c), expected counts are sums over the 144 classes of `floor((c-1-r)/144)-floor((a-1-r)/144)`, with exact integer floor. Do not estimate by percentages or counts at a convenient boundary. `BASE` is a separate category in general reconciliation/tests, always 0 in scientific batches. There is no other permitted skipped category.

## 2. Snapshot, trust-root, manifest and byte contract

Versioned structural shapes: `schemas/frontier_snapshot_v1.schema.json`, `schemas/frontier_run_v1.schema.json`, `schemas/frontier_checkpoint_v1.schema.json`, `schemas/frontier_certificate_v1.schema.json`. Each schema is a *shape constraint*; every following cross-field condition is mandatory code and test. Reject unknown/missing keys, duplicate JSON keys, non-ASCII strings, noncanonical encodings, integers supplied as JSON numbers, negative bounds, a leading + or zero-padded decimal, invalid timestamps, file traversal, oversized records, or excess object nesting. All quantity fields use base-10 canonical ASCII strings (0 or a nonzero digit followed by digits). Decimal endpoints max 8192 digits in v1 (explicit resource limit, not fixed-width arithmetic), full JSON records max 128 KiB; exceeding either REFUSES without a mathematical conclusion. Other fields use constrained ASCII identifiers, hashes, URLs and UTC dates.

Canonical bytes for each JSON record: UTF-8 of Python `json.dumps(obj, sort_keys=True, separators=(',', ':'), ensure_ascii=True, allow_nan=False)`, with no trailing newline; require byte-for-byte equality on load. All permitted fields are ASCII, integral quantities are decimal *strings*, and there are no binary floats. Hash SHA3-256 (`hashlib.sha3_256`); `H(tag,payload)=SHA3-256(ASCII("CEML-FRONTIER-1/") || ASCII(tag) || 00 || payload)`, lowercase 64-hex. Snapshot digest `H("SNAPSHOT", canonical snapshot bytes)` (no embedded self-digest). Run manifest digest `H("RUN", canonical run bytes)`. Each checkpoint or certificate has a `digest` string; hash canonical bytes of that object with ONLY its top-level `digest` member deleted, using `H("CHECKPOINT",...)` or `H("CERTIFICATE",...)` respectively. Verify raw file canonicality and digest on every read, independently in Python.

The snapshot embeds BOTH peer-reviewed published `B=2^71` and dated author-reported operational `B` with exact work-unit facts and separately named evidence tiers. The file `config/frontier_snapshot_v1.json` is a **research snapshot**, `research_only=yes`, NOT a RUN1 configuration approval; L1 must reject execution while it is unacknowledged. Run manifest selects *one* `base_kind` and `base_B` that exactly matches this digested snapshot. RUN1 operator must separately supply an explicit acknowledgment equal to `snapshot_digest + ":" + base_kind + ":" + base_B`, and a fresh authority flag recorded in local run evidence; acknowledgment is not itself evidence that the external proposition is true. No runtime URL retrieval, automatic site refresh, fallback baseline, or external work-unit assignment is permitted. World-frontier comparison is separate subsequent research.

For each independent chain, `genesis_digest=H("GENESIS", UTF8(run_digest + "|" + snapshot_digest + "|" + base_kind + "|" + base_B))`. Batch 1 `S=B` and `predecessor_digest=genesis_digest`. Every subsequent `S=prior E` and `predecessor_digest=prior committed certificate digest`. Each batch has a separately hashed run manifest but must preserve the chain's `run_id`, snapshot, base mode/B, rule/table and build identities; only its interval and predecessor change. The chain binds snapshot, run manifest's base mode and base bound, map, ruleset, table and build identity; mismatched identity is refusal. A different build may verify a prior certificate independently, but cannot silently splice an old chain into a different run-root. Distinct reruns must have distinct run IDs and chain roots; no automatic concatenation across baselines. Strict ledger audit begins at genesis, traverses each immutable committed certificate once, ensures no gaps/overlaps/duplicates/cycles, and re-verifies stored bytes and parent digests. One uncommitted or damaged predecessor blocks successors.

## 3. Scan-completeness evidence, canonical event stream and counters

**Neither counts nor a hash of self-asserted events proves a scan occurred.** Require BOTH a tightly checked native ordered stream and a *second, full, separately implemented Python reference replay of every integer in the batch* before promotion. Keep initial batches small enough for this deliberately redundant verification. For each n in [S,E), native emits exactly one ASCII event frame on a pipe (never permanent per-n files), format:
`<n>|<rule>|<steps>|<odd>|<witness>\n`
where decimal fields are canonical positive/nonnegative decimal ASCII, rule one of the five IDs or EXPLICIT; no embedded whitespace, plus signs, extra fields or huge frame (> 32 KiB). The witness is the smaller forward value for E2/Q4/S2/EXPLICIT, or the smaller reverse predecessor for P3/M9. For the five algebraic rules `steps=odd=0` denotes *no native EXPLICIT T evaluation*; their theorem witness is still recomputed by checker. For EXPLICIT `steps>=1`, `0<=odd<=steps` and witness equals the FIRST exact iterate `T^steps(n)<n`. Standard C-step count for those paths is `steps+odd`. An exhausted explicit calculation emits no successful event; retain current n as an unresolved *pending* anomaly. Every native event must carry exactly expected `n` and correct priority category; checker tests independent proof witnesses and, for EXPLICIT, exact per-step T and parity until the first descent.

`transcript_digest(c)=H("EVENTS", concat(event frames from n=S through c-1))`, including exact newline bytes. No event at/after c contributes. The independent replay generates all frames from its own Python C/T definitions, does not trust native classification or witness, and must yield identical bytes/counts/hash over the ENTIRE [S,E) before a certificate is eligible. Replay is a real second computational pass after the native scan; it is not a comparison of two cached counters, two hashes of one stream, or spot sampling. A verifier may also compare event-by-event in pass 1, but that does not replace pass 2. The independent checker must be re-invokable from an immutable certificate, snapshot, pinned source/build and predecessor chain; it reruns every candidate rather than trusting the recorded outcome.

For the completed prefix [S,c), counters `base_count`, `e2_count`, `q4_count`, `p3_count`, `m9_count`, `s2_count`, `explicit_count` and `unresolved_count` are canonical decimals. `base_count=0` in a frontier run; `unresolved_count=0` in a completed prefix (a current failed n is represented only in `pending`, not advanced). Require `sum(seven completed categories)=c-S`, expected residue counts for every rule including EXPLICIT, and `explicit_count` equals the number of completed explicit frames. `explicit_attempts=explicit_count + pending_attempt_indicator` is a separate operating count; never add it to the coverage sum. Track `explicit_t_steps`, `explicit_odd_steps`, `explicit_standard_steps=explicit_t_steps+explicit_odd_steps`, and optionally elapsed measurements (non-scientific) in a separate telemetry-free local log. Checker recomputes these independently; reject overflow/truncation, modulo ambiguity or mismatched totals. A claimed prefix cursor alone cannot justify promotion. For a full committed batch `c=E`, `pending=null`, `unresolved_count=0`, all counts and both full-pass digests agree.

## 4. Bounded one-batch transaction, exact recovery, failures

One native worker process and one Python driver only; *no concurrency*, distributed work, server communication, remote dependencies, GPU mode, imported compressed sieve, background jobs or source auto-update. Exactly one active batch per chain. Run a single native scan with a pinned `max_t_per_explicit` in 1..100000 and `max_total_t` in 1..2000000, with `E-S` in 1..14400. Exceeding any guard, operand/memory ceiling, input size or wall budget produces an incomplete/refusal record and stops; no default 0=infinite. Calibration of feasible batch sizes is **UNKNOWN pending L1**. Set numeric budgets explicitly in manifests; do not claim hardware-based speed.

Checkpoint record `CEML-FRONTIER-CKPT-1` is **new**, not CEML-CKPT-1. It contains immutable run digest, batch S,E, base choice, snapshot/rules/build hashes, predecessor, next_n, generation number, prior generation digest, counters of *only* fully completed prefix [S,next_n), deterministic prefix transcript digest and T-step totals, with `pending` either null or a bounded unresolved current-n object. `next_n` is precisely the first not yet successfully certified integer; it NEVER advances over pending work. No partial trajectory state may be silently used as a proven result. The native process may recompute an interrupted explicit trajectory from its original n, exactly. On resume re-derive every prefix event in Python and in native, compare per-event sequence, digest, counters and identities to checkpoint BEFORE continuing. Incomplete batch checkpoint is useful engineering progress evidence, NOT durable scientific prefix coverage.

There are only two rotating, self-contained checkpoint slots `ckpt.0.json` and `ckpt.1.json` (<=128 KiB each) plus one final immutable `certificate.json`, all in a single dedicated same-volume directory. Each new generation: construct canonical complete bytes with prior valid generation digest and incremented generation; create a new unique same-directory temporary file exclusively; write all bytes; verify exact write length; flush file and close; atomically replace the *older* checkpoint slot with write-through rename; where supported flush directory; re-read and validate new slot including logical prefix checks before treating it as restartable. NEVER overwrite the sole last verified valid generation; if the latest slot is broken, fall back only to the prior independently verified generation and reprocess a suffix, with a recorded integrity warning; contradictory valid forks, broken identity/chain or no valid prior slot fail closed. An optional latest pointer is untrusted. Generation wrap/duplicate/non-monotonicity is refusal. No Git auto-commit of local records.

After native reaches E, construct a provisional candidate certificate in memory. Require separate COMPLETE Python reference replay, revalidate predecessor certificate, snapshot and manifest, reconcile all exact counters and both event hashes, and insist `pending=null`. Then write a unique `certificate.tmp` exclusively, flush/close, atomic **no-replace** same-directory rename to `certificate.json`, flush directory where supported, re-open, re-hash and re-verify all content and predecessor dependencies. **Only presence of a valid canonical immutable final certificate is COMMITTED**. Any exception before final certificate validation is not COMMITTED; a proposed next batch MUST refuse an uncommitted predecessor. If final filename exists but is corrupt or contradictory, fail closed; never overwrite or auto-repair. Orphan temp files never become evidence and require review/cleanup outside certifying code. Committed chain extension uses the verified certificate digest only.

Power failure, storage/controller loss, NTFS/OS cache and directory-flush support make durability conditional; file flush + write-through rename is not a formal guarantee against sudden power loss or malicious rollback. Never claim ACID/durable against power loss without measured platform support and operator backup; loss of new slot or certificate means revalidation/recomputation, not automatic promotion. A hash alone is tamper-*evident under retained independent roots*, not authenticated against an adversary who replaces all files and hashes. Preserve an externally copied genesis/snapshot digest and independently check the Git commit/build identity. Missing checkpoint with no valid predecessor halts rather than inferring completed work. Rollbacks are detected where a trusted external latest digest/monotonic evidence is available; absent that, explicitly report rollback-detection limitation.

## 5. Smallest local implementation and unavoidable tests

Reuse read-only existing public `src/ceml_oracle.c` elementary C/T/U definitions, `src/ceml_sha3.c` digest primitive and only carefully extracted Win32 file/flush/rename primitives. Do not call, ungate or change the legacy `ceml.exe`, scheduler, CEML-SCI-1 or CEML-CKPT-1. Build a **separate** `ceml_frontier.exe` with checked MSVC C17 flags `-nologo -std:c17 -W4 -WX -O2 -MD -D_CRT_SECURE_NO_WARNINGS -Brepro -external:I. -external:W0`, link with locally reconstructed `gmp_public.lib` and `libgmp-10.dll` as already pinned, under `local/frontier/build`. No runtime downloads; if the already pinned offline cache is absent, REFUSE and request separate operator provisioning. Do not alter the GMP pin or pretend the full SDK closure is content-hashed. Python code uses only standard library; exact arithmetic in Python `int`. Build manifest hashes inputs, executable, DLL, headers, source, toolchain versions, parity-table bytes, test-suite revision; compiler stdout/hardware identity are not evidence. Build and test paths must be network-disabled and checked not to import HTTP, sockets or telemetry.

GMP `mpz_t` represents all dynamic n and intermediate states; no `unsigned long` for an endpoint or T result. Before converting size/budget to `unsigned long`, prove range <=100000/2000000 and checked exact equality after roundtrip; `size_t` byte lengths and output buffers must be bounded with checked additions/multiplication and allocation failure, including LLP64 Windows `unsigned long`=32-bit. No unchecked 3*n+1 in machine types: always GMP `mpz_mul_ui/mpz_add_ui/mpz_divexact_ui`, with required odd/even and divisibility preconditions. Reject a negative/zero start, noncanonical input, GMP parsing error, step-counter increment overflow, ambiguous/failing 64-bit codec, huge operand resource threshold, truncated pipe line, missing process exit code, and misleading native 0-step "success". GMP limb/bit-count limits of the pinned build remain an explicit **resource refusal**, not mathematical integer limitations. Every fixed-width native counter must be separately checked against budget before mutation. Native never bypasses Python's preceding source/status/run authority check.

Independent L1 acceptance (no scientific execution):

## 6. Claim tiers and refusal rules

`RULE_PROVED_CONDITIONAL`: P1 elementary theorems given A(n), not independent external B. `ENGINE_TESTED`: L1 fixtures only. `BATCH_CONDITIONAL_PUBLISHED`: native plus independent full replay, contiguous committed chain from peer-reviewed 2^71, claims conditional on paper's computational baseline. `BATCH_CONDITIONAL_OPERATIONAL`: same but on separately selected author-reported live B, *not* an independently reproduced global prefix. `INDEPENDENT_REPRODUCTION` requires genuinely independent repeat evidence distinguished by code/build. `GLOBAL_FRONTIER_EXTENSION` requires contemporaneous independent evidence for all earlier work units and priority/novelty; no automatic promotion by CEML's runner. Incomplete, checksum mismatch, failure, checkpoint-only proof, duplicate/gap, old C1 PASS, or resource exhaustion never earns any batch tier. Report both published and live source UTC timestamps, run/retrieval UTC, exact exclusive intervals, assumption tier, step counts and whether independent replay was performed. All claims finite and conditional, not Collatz-universal proof.

**Stop condition:** P2 freezes ONLY this contract and files. L1 implementation awaits separate owner invocation; RUN1 a still later independent owner invocation.
