**Actual algorithm** (paper §3.1, ALGORITHM.md): in the accelerated shortened Collatz map T(n)=n/2 (even), (3n+1)/2 (odd), track n+1 during odd phases. Perform repeated groups of alpha = ctz(n+1) multiplication by 3^alpha after division by 2^alpha, then beta = ctz(n−1 after switching back) halving; repeat until below original n0. Paper's T/T1 identities (§3.1) justify the representation change. Tables of powers of three avoid per-step multiplication/addition. These are exact integer identities **only if** width, CTZ domain, alpha cap and overflow branches are handled safely.

**Actual CPU paths:** worker.c declares 128-bit arithmetic, 41-element 64-bit power-of-three LUT and conservative pre-multiplication width checks; when enabled with _USE_GMP, mpz_check2 resumes exceptional paths and increments an overflow counter. Without GMP the exceptional branch aborts, it does not magically prove a result. Its precalculation/calc routines apply low-bit sieves and 3^k filters, then evaluate surviving high parts; configuration macros alter semantics/performance. Source must be audited under an exact build matrix, not described as one immutable algorithm.

**Actual GPU paths:** gpuworker.c creates OpenCL buffers, transfers the sieve, launches kernel32 or kernel32-precalc and retrieves per-thread checksum and maximum-offset arrays; kernel32.cl loops n0 from each subrange's n_minimum+3 in strides of 4, filters with IS_LIVE and optional USE_SIEVE3/USE_SIEVE9, and uses private 128-bit state and grouped CTZ/LUT processing. The shown kernel records a zero alpha checksum on a 128-bit fast-path overflow and exits its thread's loop; the inspected gpuworker.c host checks for any zero and emits ABORTED_DUE_TO_OVERFLOW / aborts. **It is not a proven automatic GPU GMP fallback.** The CPU GMP fallback is distinct. GPU branch divergence, memory placement and OpenCL 128-bit compiler support are correctness/performance constraints, not guaranteed speedups.

**Sieves/scale actually documented** (2025 §§3.2–5): modulo-9 reverse-coalescence can remove 4/9 of raw starts versus 1/3 modulo-3, but larger 3^k yields diminishing elimination (paper quotes 45.95% at 3^6). The 2^k sieve is a one-bit per low-residue mask derived from k-step affine trajectories, not a statement that every excluded start actually had its full orbit run. Experimentally best tested sizes: CPU **2^34 bits (~2 GiB)**, GPU **2^24 bits (~2 MiB)**; compressed sieves exploit approximately 50 repeating 64-bit patterns with LUT indices and reduce distribution size. Compression is an engineering representation of a mathematical table, not an independent proof of its safety. Concurrent processing of congruence classes improved CPU in the authors' tests and did not improve the GPU in their configuration. This invalidates assuming "fewer candidates always means faster GPU".

**Distribution/protocol actually documented:** server, HPC scheduler-launched multithreaded clients, CPU/GPU workers; TCP assignment/return protocol in doc/PROTOCOL.md, 2^40 starts per work unit, up to 2^32 units. The paper reports 322 bits/server unit (timing, overflow count, max offset, alpha checksum, client ID, flags), 12,395 CPU-years and 159 GPU-years consumed cumulatively by heterogeneous historical workers, and best-tested 52.1× GPU/CPU and 1335.9× first CPU/best GPU improvements. The paper does **not** expose a standalone succinct proof that each recorded checksum implies all starts were traversed. Its checksum is a diagnostic/proof-of-work fingerprint, not a cryptographic exhaustive-work SNARK.

**CEML versus Bařina:** frozen CEML-FRONTIER-2 / accepted CEML-SESSION-I2 uses ascending ~9,999-start batches, explicit exact proofs E2/Q4/P3/M9/S2K4-03, GMP-first native C and separately implemented Python per-start full batch replay, digested records, atomic recovery and an independent full publication audit; strictly conditional operational baseline. ## 3. Mathematics and candidate exclusions

**Invariant (conditional strong induction):** fix externally assumed A(B): all positive m<B reach 1. Process all n≥B in strictly increasing order with committed lower batches and a provisional uninterrupted current prefix. It suffices to certify either an exact finite T^j(n)=m with 1≤m<n, or an exact smaller p<n with T^j(p)=n. In the reverse case, convergence of p implies convergence of n because n lies on p's trajectory. A GPU scheduler with arbitrary independently processed n cannot assume A(n) merely because n is assigned; it needs an earlier committed basin or a separate acyclic dependency closure. n=1 and 0 are special; no 0 inclusion or circular proof is permitted.

**2^k lift:** for n=2^k q+r, 0≤r<2^k, parity is determined by r for the first k shortened steps and T^k(n)=3^a q+T^k(r), where a is the number of odd steps on r's k-step path (T(0)=0 permissible for the *table identity* only). An all-q descent is valid exactly when (2^k−3^a)q>T^k(r)−r throughout the domain. If 2^k>3^a and q starts at q_min, checking the inequality at q_min suffices universally; if coefficient negative, no unbounded upper tail can be removed by that k-step criterion. A larger bitmap or compressed representation without an independent derivation and boundary test is NOT proof-safe.

**New, mathematically PROVED candidate classes for a prospective sieve, NOT activated in CEML:** for every q≥0,
- n=32q+11 has parity-path base 11→17→26→13→20→10, with three odd steps; **T^5(n)=27q+10**, giving n−T^5(n)=5q+1>0.
- n=32q+23 has path 23→35→53→80→40→20, also three odd steps; **T^5(n)=27q+20**, giving n−T^5(n)=5q+3>0.

The affine lift proves these statements for **all** q≥0, not just fixtures. Both residues are odd ≡3 mod4 and are not already covered by the S2K4-03 low-bit predicate; P3/M9 may pre-empt some members. Over one period lcm(32,9)=288, independent residue precedence counting gives **10 additional starts / 288** compared with the prior 15/144 explicit count, so prospective explicit density is **20/288 = 1/14.4 ≈ 6.9444%**, versus 15/144=10.4167% at entry. This is a 33.33% relative decrease in explicit candidate counts, **NOT** a 33.33% elapsed-time improvement. Precedence/integer count must be independently reproduced in a future acceptance matrix before implementation.

**New, mathematically PROVED reverse-coalescence subfamily for study:** for q≥0 let n=91+729q, p=63+512q. Then 1≤p<n (n−p=28+217q), and **T^6(p)=8n**, followed by three halving steps **T^3(8n)=n**. Proof: 8n+1=729(1+8q); writing v_0=8n and v_j+1=2^j3^(6−j)(1+8q) for j=1,...,6, all v_j are positive odd integers and T(v_j)=v_(j−1), while v_6=p. Thus every such n coalesces from an earlier certified p. In this family n≡1 mod9, so P3/M9 do not subsume it; among q mod16, q=0,4,12 survive the prior five filters and the new 2^5 filter (q=8 is removed by S2K). This gives **3 distinct surviving classes per 11,664 integers** (density ~0.02572% of all starts) on top of the 2^5 prospective sieve. This is elementary mathematics, **not an originality/novelty claim**; source-prior-art beyond the paper's existing 3^k construction must be checked before treating it as publishable.

**Independent fixture scope, not computation science:** arithmetic cross-check of n=91+729q against the nine-step inverse/forward identity for q=0,...,15, including priority ownership and p<n, returned 16/16 identities. Separate exact 2^k mathematical enumeration for k=4,...,12 found for k=5 the two surviving new classes r=11,23 (10/288 after baseline precedence). These small checks support algebraic identities, not a GPU kernel, safe compressed LUT loader or verification interval. Higher k can have nonmonotone *one-specific-k* performance/coverage; combining all certified k≤K is a different design choice.

**Independent sieve validation design:** generate reference masks independently from exact integer T and a proven universal q_min inequality; compare two implementations (e.g. Python bigint and separately written C/GMP) for *all* 2^k residues at manageable k; prove compressed-map periodic indexing/extraction exactly reproduces the uncompressed reference, check 0/1/negative-domain exceptions, boundary around 2^64/2^128, all classes and nonmultiple-of-period unit endpoints; fault inject flipped bits, swapped endian order, wrong n0, missing/duplicated unit, false overflow and broken q_min; reject any disagreement. No finite sample alone proves a k=34 table; a symbolic recurrence plus trusted generation/verification or an explicit checked table digest tied to a fully documented generator is needed. Tao's logarithmic-density-one theorem does not remove any specified single n.

## 5. Evidence architecture, adversaries, blockers

A defensible full-scale pipeline should separate **(i) proof-checked sieve/generator version**, **(ii) untrusted optimised workers**, **(iii) durable lease+coverage ledger**, **(iv) independent verifier/cross-checker**, and **(v) only then public evidence/claim gate**. Proposed per-unit manifest binds integer unit ID/range/endpoint policy, mathematical sieve version and proof digest, worker implementation source/compiler/device/config, input assumption provenance, result checksum/counters/overflow/mx offset, attempts/lease/worker identity, verifier decision, separate independent rerun identity, timestamps and chain/Merkle inclusion; the coordinator rejects holes, conflicting results and unverified partial units.

**Hashes and checksums are not standalone correctness proofs:** a hash binds bytes, not the truth of what a worker actually evaluated. Summed CTZ alpha values can collide (and are not injective over trajectories); a worker may skip starts, mishandle overflows, take a faulty GPU branch or forge a plausible checksum. A Merkle root of such hashes only commits to the reported ledger. Public independent validation requires either a reproducible full recomputation of every candidate (possibly by independent distributed implementation) or a newly developed mathematically sound succinct argument; partial duplicate sampling yields a **probabilistic** reliability claim with explicitly defined random selection, threat model and detection rates, not exhaustive proof. For independent random sample fraction s of units and f_bad independently uniformly distributed corrupted units, detection probability under sampling without replacement is 1−C(N−f_bad,sN)/C(N,sN), provided untrusted workers cannot predict/adapt to sampling and corruption is unit-detectable; this does not protect against shared-source bugs or targeted uncovered work without stronger assumptions. A practical plan can commit assignments/results before unpredictable audit selection and require *every* unit to have at least one accepted deterministic worker execution plus a stronger requirement for frontier-critical units. Claims must remain conditional on the chosen integrity model.

**Blockers / mitigations:** (1) moving source and contested assignment → timestamped immutable source snapshots and registration in author's queue if permitted; (2) GPU correctness/overflows/compiler dependence → independent reference and adversarial overflow fixtures, no silent wrap; (3) large compressed sieve bug → mathematical generator equivalence, proof of all compressed-index cases; (4) nonmonotone GPU speed with high-power sieves → actual end-to-end controlled benchmarks, elapsed-time metric; (5) absence of public full lower-ledger reproduction → honest author-reported conditional bound and independent whole-unit audits; (6) audit labor/cost → pilot selected full 2^40 units on separately authorised resources and cost model; (7) parallel scheduler holes/duplicates → persistent interval set and complete contiguous-prefix proof from ledger, immutable retries and no leap across unresolved units; (8) trust/delayed publication → separated scientific worker, validator and publisher with explicit decision thresholds.

**Independently testable hypotheses, not accepted results:**

**H1 (proof-safe 2^5 sieve):** the exact 32q+11 and 32q+23 exclusions, independently generated and integrated only in *freshly versioned* experimental code, will cut post-P1 explicit candidates from 15/144 to 20/288 without errors or unaccounted endpoints. Validate proof symbolically, compare two independent residue enumerators for a full joint period and run adversarial high-bit fixtures. Runtime benefit remains unknown.

**H2 (high-k sieve economics):** a compressed 2^k table generated from exact affine inequalities, at k=16,24,34 depending on architecture, will outperform a smaller table on *some* real device only after copy, cache, kernel divergence and verifier amortisation. Measure end-to-end seconds per accepted 2^40 unit and error/refusal frequency, not bitmap-hit rate.

**H3 (reverse-coalescence research):** 91+729q family and its general 2^e / 3^k reverse templates provide additional demonstrably sound residue sets not already killed by P1 and 2^5. Prove for all integer parameters under explicit positivity/integrality and count unique classes after precedence; audit Bařina 3^k prior art and measure whether a GPU branch implementation helps at all. No mathematical novelty claimed.

**H4 (trust economics):** independent verifier costs more than worker alpha-checksum validation but can achieve a defensible end-to-end error model using signed immutable manifests, private unpredictable unit auditing and full independent replica runs on a rigorously selected sample. Test adversarial skipped-unit/overflow/shared-bug scenarios; decide *which claims* remain valid, distinguishing probabilistic from exhaustive verification.

**H5 (capacity reality):** effective useful units/second per GPU-equivalent across end-to-end units may be below the 5s homepage hypothesis; benchmark 3–5 hardware/configuration classes under an separately authorised, nonpublication engineering protocol before any 100/1000-equivalent forecast.
