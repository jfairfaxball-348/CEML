## Design choices, tradeoffs, residual risks

1. Chose one GMP-only C17 worker, not unchecked 128-bit arithmetic. Removes a complex overflow switch at modest potential CPU cost (quantitatively UNKNOWN until L1). Single Python standard-library orchestrator + independent checker; original C1 direct oracle and pinned offline GMP package may be reused. A fixed small 16-class table is built and checked, not downloaded. No old route/scheduler/huge sieve.
2. Bounded 14400-start maximum batch and two full passes (native ordered stream, separately independently computed Python events for every n). This addresses the principal gap in P1: counts and signed-off cursors alone do not establish a real complete traversal. Exact event equality and full replay provide independently checkable computation, still contingent on the checker implementation and software integrity, not formal proof of execution or tamper-resistant authentication.
3. Version-1 checkpoint stores a completed prefix only with `next_n` equal to first uncompleted start, and any unresolved work outside its certified count. A two-slot generation store plus re-execution/replay on resume eliminates dependence on deserializing SHA3 internal state and avoids promoting incomplete work. It sacrifices some runtime efficiency deliberately. Single-file final-certificate rename is the commit point, strictly chained.
4. SHA3-256 domain-separated record digests and locally retained/externally pinned genesis identify alterations if comparison roots survive. They do **not** prevent a malicious party rewriting all records, or guarantee recovery from sudden power failure/disk controller failure. No power-loss guarantee is asserted for Windows `MoveFileExW` even with `FlushFileBuffers`; after power loss re-evaluate.
5. JSON schema constraints are structural; explicit canonical-byte verification, exact integer floor-count tests, max lengths, origin proof and chain order must be checked in code. No manual overrides on mismatch. A locally frozen source snapshot is **research-only** until RUN1 operator acknowledgment. A published-mode chain cannot teleport to the live pointer; an operational-mode chain openly depends on the author's live report.
6. L1 must run TESTS only, not an interval over the scientific frontier. RUN1 can later choose just 144 starts with measured step budgets and explicit authorisation. No hardware speed is extrapolated from the author's GPU or C1 4096-bit calibration.
